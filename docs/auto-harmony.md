# 自動和弦與伴奏

新增歌曲與現有歌曲共用 `harmonizer.harmonize_song()`。不需要安裝 MuseScore QML 外掛；此功能直接處理本網站的歌曲 JSON。

## 使用方式

- 既有四首正式歌曲：從原有和弦音符辨識代號，保留原來的和弦／貝斯音軌。
- 四首 MusicXML 試轉：已儲存自動和弦代號、逐小節和弦伴奏與根音／五度貝斯。
- 後續執行 `tools/trial_musicxml.py` 時，轉換結果會自動加入和聲。原有的單聲部、固定四分音符拍號、完整小節等匯入限制仍適用；本次沒有新增瀏覽器上傳或 MSCZ 匯入。來源 MusicXML 若有 `<harmony>`，這個簡易試轉器會明確拒絕，避免忽略原有和弦後改配；需先擴充來源和弦解析器。
- 放進 `data/songs/` 的新歌 JSON，在下次啟動載入時也會自動補齊；這層只更動記憶體，不改寫來源檔案。試轉目錄維持獨立，不自動混入正式曲庫。
- 網頁五線譜上方顯示中音薩克斯風寫定調的和弦，例如實音 Eb／Bb7 顯示 C／G7；合成伴奏仍播放實音。滑鼠停留代號可查看實音與是否為自動推定。
- 原有的和弦／貝斯音量、靜音與獨奏控制可直接使用。

若要將之後新增的既有 JSON 寫回檔案，在專案根目錄執行：

```bash
# 預覽；不寫入
.venv/bin/python tools/add_harmony.py
# 寫入正式與試轉兩個目錄
.venv/bin/python tools/add_harmony.py --write
# 指定其他歌曲目錄
.venv/bin/python tools/add_harmony.py /path/to/songs --write
```

批次先驗證全部曲目，再備份不同內容的檔案至 `.backups/harmony-時間/`，並以暫存檔取代各個 JSON。manifest.json 記錄原檔與備份對應；若寫入中途失敗，可以依該對應還原。原八首首次備份原位於 `.backups/harmony-20261022-090552-446136/`；功能與曲目測試完成後已封存至專案外 `/home/sweet/.local/state/sax-play-along/archives/harmony-20261022-090552-446136-cleanup-20261022-111044.tar.gz`。未來工具產生的 `.backups/` 仍不納入 Git。

## 資料與規則

新增欄位 `chordSymbols`：

```json
{"symbol":"Eb", "root":3, "quality":"", "start":0, "dur":3, "source":"automatic"}
```

`root` 是實音音高類別 0–11；`start`、`dur` 沿用歌曲的拍位單位；`source` 為 automatic 或 existing-notes，匯入者亦可提供自己的來源資訊。自訂和弦至少提供 symbol/start/dur；支援的名稱會自動補 root/quality 並產生缺少的伴奏。未知名稱可顯示但不猜測其伴奏音符。

優先順序：既有 `chordSymbols` → 原有 `chords` 音軌辨識 → 缺少和聲的小節依旋律推定。同一小節已有任何和聲區間，即不另加競爭的旋律配法；原有每小節多和弦照常顯示。無法辨識的音組保留音符，不強加代號。已存在且非空的貝斯音軌完整保留。重複處理不產生額外音符或代號。

辨識支援大三、小三、屬七、大七、小七、減三及增三和弦，包含轉位。增三和弦具有對稱性，無法僅由音高集合唯一判定根音，本版以最低音命名。生成伴奏為簡單原位配置，不執行最佳聲部進行。

自動推定只適用目前資料模型的大調、固定 2/4、3/4、4/4 等四分音符拍號，以 keyConcert 為主調。候選 I、IV、V7、vi、ii，依音符在小節內的實際持續時值與強拍加權，跨小節持續音亦計入；整小節休止不新增和聲。此版不分析小調、轉調、借用和弦或完整終止式。明確標記非大調或非四分音符拍號時，載入流程記錄提示並保留原資料，不自動推定。

四首 MusicXML 的寫定／實音基準仍沿用先前暫定假設（-9 半音，部分來源缺調號）；本次生成的和弦是練習建議，不代表已核對原作編曲。原始 MusicXML、旋律、符幹與連桿資料不因和弦回填而改變。
